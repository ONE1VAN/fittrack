# FitTrack

Десктопний застосунок для фітнес-клубу на Python + Kivy. Три ролі: **клієнт**, **тренер**, **адміністратор** — кожна зі своїм інтерфейсом і набором дій: розклад занять з бронюванням, абонементи з заявками на купівлю та підтвердженням, відео-тренування з коментарями та лайками, СКУД-картка з QR-кодом, журнал обладнання, керування користувачами.

## Вимоги

- Python 3.10+ (тестовано на 3.11)
- Windows / macOS / Linux

## Запуск

1. Створіть та активуйте віртуальне середовище:

   ```
   python -m venv .venv
   .venv\Scripts\activate            (Windows)
   source .venv/bin/activate         (macOS / Linux)
   ```

2. Встановіть залежності:

   ```
   pip install -r requirements.txt
   ```

3. Запустіть застосунок:

   ```
   python main.py
   ```

При першому запуску в `data/fittrack.db` створюється SQLite-схема та засіюється стартовий стан.

## Стартовий акаунт

Сід створює одного користувача-адміна. Тренерів і клієнтів адмін додає сам через вкладку `КОРИСТУВАЧІ` → `+ НОВИЙ КЛІЄНТ` і потім `ЗМІНИТИ РОЛЬ`, якщо треба зробити тренером.

## Ролі та можливості

**Клієнт**
- Bottom-nav: Головна / Розклад / Абонементи / Відео / Профіль
- Бачить hero-карту активного абонементу (днів залишилось, заморозки, тип)
- Бронює та скасовує заняття у спільному розкладі
- Купує абонемент через двоетапну заявку: підтвердження → відправка адміну
- Дивиться відео-тренування, ставить лайки (червоне серце ♥), пише коментарі та відповіді
- Сканує QR-картку СКУД зі свого профілю

**Тренер**
- Bottom-nav: Головна / Розклад / Відео / Профіль
- Створює нові заняття (категорія, зал, дата/час/тривалість)
- Видаляє свої заняття з підтвердженням (каскадно скасовує бронювання)
- Бачить учасників занять, відмічає присутніх / відсутніх (іконки-кружечки: зелений ✓, червоний ✗) або виключає клієнта (мінус у червоному колі)
- Завантажує відео з файлового пікера, thumbnail генерується автоматично з першого кадру

**Адміністратор**
- Bottom-nav: Головна / Розклад / Відео / Профіль
- KPI-плитки: активні абонементи, відвідування сьогодні, дохід місяця, retention
- Стрічка останніх платежів та блок «потребують уваги» для обладнання з відкритими заявками
- Створює нових клієнтів (з автоматично запропонованим RFID), змінює ролі, видаляє користувачів
- Обробляє заявки на абонементи: підтверджує (створює `subscriptions` + `payments`) або відхиляє
- Керує абонементами: заморозка / розморозка / анулювання (soft) / видалення (hard)
- Закриває заявки на ремонт обладнання кнопкою `ПОЗНАЧИТИ СПРАВНИМ`

## Технічні деталі

- **БД** — SQLite (one-file `data/fittrack.db`), нормалізована схема в 3НФ із зовнішніми ключами. У `db._run_migrations` накатуються таблиці, які з'явились після першого релізу (`subscription_requests`), щоб існуючі бази оновлювалися без втрати даних.
- **Шляхи** — `app/paths.py` визначає writable-каталог: на десктопі у dev-режимі це папка проєкту, на запакованому Windows-білді — `%APPDATA%\FitTrack\`, на Android — `App.user_data_dir`.
- **Аутентифікація** — bcrypt, з fallback на sha256 (якщо bcrypt недоступний). Сесія — синглтон у `auth.Session`.
- **Відео** — `kivy.uix.video.Video` через ffpyplayer, з `eos="loop"` для повторного відтворення. Хвостове приглушення (`volume=0` за 0.5 с до кінця) гасить дубльоване аудіо на файлах з битими DTS, при пере-зацикленні гучність відновлюється. Прогрес-бар — read-only, без перемотування.
- **QR СКУД** — генерується з `users.card_id_skud` через бібліотеку `qrcode`, рендериться в PNG, далі в текстуру Kivy; вирівнюється по центру через `AnchorLayout`.
- **Заявки на покупку** — клієнт натискає `ПРИДБАТИ` → popup з підтвердженням → запис у `subscription_requests` зі статусом `pending`. Адмін у вкладці «Заявки на абонементи» підтверджує → `SubscriptionRepo.sell` створює одночасно `subscriptions` і `payments`, що автоматично відображається в KPI та стрічці платежів адміна.
- **Видалення відео** — `VideoRepo.delete` каскадно прибирає файл `.mp4` і thumbnail `.jpg` з диска плюс рядок з БД; лайки і коментарі видаляються каскадом FK.
- **Каскадне видалення користувача** — `UserRepo.delete` видаляє рядок з `users`; через FK з `ON DELETE CASCADE` зникають усі його підписки, бронювання, заявки, коментарі та лайки. Записи в `payments` зберігаються (sub_id переходить у NULL).
- **Заглушення лог-шуму** — у `main.py` додано logger filter, який пригнічує повідомлення Kivy «Error loading <file>.mp4», що генеруються базовим класом `Image` під час ініціалізації Video-віджета (відео все одно успішно відтворюється через ffpyplayer).
